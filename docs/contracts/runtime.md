# Contract: solver runtime

`autan-run` runs a [solver input](solver-input.md) and writes the [run directory](results.md). Its invocation, exit statuses and inputs are in solver-input.md; its outputs in results.md. This page fixes the seam between the runtime and the physics: what a discretisation implements so that the runtime can drive it. Header: `runtime/include/autan/runtime/physics.hpp`, library `autan::runtime`.

## Division of work

The runtime owns the iteration loop, the convergence test, stop signals, the run directory, the history (residual names, monitor cadence, force coefficients) and `solution.cgns`. A physics owns its state arrays (host or device), its kernels, their schedule and their precision. The runtime never touches device memory.

## Physics

A physics is constructed from a `PhysicsContext` (the assembled mesh, its FP64 geometry and the parsed solver input), with its state set to each cell zone's `initial` values, or to `start` when the input has one (below). The context's references stay valid until the run ends; a physics may keep a copy. Its `log` writes events to the run's `log.jsonl` (results.md): level, source, message, and optionally a registry code and data; the runtime stamps the time and the iteration. For a verification case, `input.verification->text` holds the `autan.mms/1` document the runtime read and checked: the physics takes the boundary data, source terms and auxiliary fields from it (solver-input.md, `verification`). For each `oracle-state` condition the runtime reads the face-state file before any directory exists, checks its hash (`E0420`), document (`E0420`), mesh (`E0422`) and zone coverage (`E0423`), and pairs every face of the zone with one row by centroid ([face-states.md](face-states.md), `E0421`); `boundary_states` then holds, per face zone index, the zone's states in mesh face order (5 × its faces, component-major), and the run directory archives the file under `states/`. For an input with `initial_state`, the runtime reads the file once before any directory exists, checks its hash and document (`E0508`), mesh (`E0509`) and row count against the fluid cells (`E0510`), and pairs every fluid cell of the whole mesh with exactly one row by centroid ([initial-state.md](initial-state.md), `E0511`); `PhysicsContext::initial` then holds `Density`, `VelocityX`, `VelocityY`, `VelocityZ` and `Pressure` of the owned cells (NaN in solid cells), the physics starts its fluid cells from them, and the run directory archives the file under `states/`. It implements:

On several ranks, or on one with periodic pairs, `mesh` and `geometry` are those of this rank's part ([partitioning.md](../design/partitioning.md)): its owned cells, then two layers of ghost cells with their geometry filled, a periodic face being an interior face to an image ghost. `ghosts.forward(components, space, stream)` fills the ghosts from their owners on this or another rank (host or device memory; device memory on the run's `stream`, `E0145` in a build without CUDA). A physics calls it before any loop that reads ghost values and loops over owned faces and cells only. On one rank without pairs there are no ghosts and `forward` does nothing. Fields, norms and scales cover the owned cells; faces passed to `wall_fields` and `loads` are faces of `mesh`.

## Devices

With `devices.kind = cuda`, each rank runs on CUDA device (its rank among the ranks of its host) modulo (the devices it sees), made current on the thread that calls the physics, with a non-blocking stream of its own: `PhysicsContext::device` and `PhysicsContext::stream` (a `cudaStream_t`); on the CPU they are -1 and null. The log's `cuda` event names rank 0's device. Nothing falls back to the CPU: a kind this build does not drive is `E0706` (`data.path` `devices.kind`), and a CUDA build that sees no device is `E0807` (`data.visible`, `data.needed`), both before any directory exists.

## Cell order

By default `autan-run` renumbers the mesh's cells in reverse Cuthill-McKee order (`rcm_order`, [mesh.md](mesh.md)) before it partitions them, so that neighbours sit close in memory, and logs it (`order`, `seconds`). The physics computes on that order; every output keeps the mesh's numbering: fields by `cell_global_id`, wall fields, loads and face states through the renumbered faces' source faces, the diverged cell by its mesh index, and `PhysicsContext::face_global_id` and `face_reversed` through the renumbered faces' source faces and flips. The geometry is computed on the mesh as read and carried through the renumbering (`renumber_geometry`), so it has the same bits in either order. `AUTAN_CELL_ORDER=input` keeps the mesh's own order, the only other value, and logs a warning. The order changes the order of a physics' face sums, so `reproducibility` "run" repeats bits for the same input in the same order; results in the two orders agree bit for bit for a physics whose sums do not depend on it or that orders them by the global keys ("ranks"), to a few units of the precision's epsilon over the explicit steps of the Euler physics, and only at convergence for a steady run, whose smoother and agglomeration follow the cell order.

## Ranks

A physics registers whether it runs on several ranks (`PhysicsRegistry::add`, `several_ranks`); one that does not is `E0706` on several. Under a launcher (`mpiexec -n N autan-run …`), every rank reads the input and the mesh, and partitions it with METIS, seeded, weighting each cell by its face count, so all ranks agree on the parts; the log's `mpi` event gives each rank's owned and ghost cells. A launcher starting several ranks of a build without MPI is `E0146`. Every member of `Physics` is called on every rank, in the same order. Rank 0 writes the run directory: `history.jsonl`, `run.json`, and `solution.cgns`, whose fields it gathers by mesh cell and wall face. Its `log` writes every event; other ranks' warnings and errors carry `data.rank`.

`PhysicsContext::ranks` reduces over the ranks: `sum` of `ExactSum`s (`runtime/include/autan/runtime/exact_sum.hpp`), `min`, `max`, and `argmin(value, id)` (the least value and its id, the least id among equal values), all collective, with the same bits on any number of ranks. `PhysicsContext::cell_colours` and `n_colours` give each cell's colour in the global distance-1 colouring of the mesh (`colour_cells`, [partitioning.md](../design/partitioning.md#colouring)): a smoother that sweeps the colours, exchanging ghosts after each colour, updates every cell as on one rank. A residual norm, a load or any sum a physics reports is summed with `ExactSum`, an exact accumulator rounded once to the nearest double, then with `ranks.sum`: its bits do not depend on the order of the terms nor on the number of ranks. With `reproducibility = "ranks"` ([solver-input.md](solver-input.md)), the runtime computes on a partition even on one rank and gives the physics each face's global key, `PhysicsContext::face_global_id` and `face_reversed`, next to `mesh.cell_global_id()` and `mesh.ghost_translation()`: a physics that sums each cell's faces in increasing `face_global_id`, evaluating a reversed face in its global orientation ([partitioning.md](../design/partitioning.md), Determinism), writes on N ranks the history and the solution arrays of a run on one, bit for bit; a physics that cannot is `E1109`. In the other modes the keys are given too, and a run on several ranks logs an info event (`mode`, `ranks`) saying that its results depend on the rank count. `ExactSum` costs 1.9 ns per term on a GB10 core against 0.5 ns for a plain sum. On the device, `gpu::exact_sums<K>(n, term, out, stream)` (`runtime/include/autan/runtime/exact_sum.cuh`, CUDA or HIP) sums K terms per item into `ExactWords` that `gpu::to_host` turns into the host's `ExactSum`s, with their bits whatever the launch shape: lanes add their limbs per warp with shuffles, then with integer atomics, whose order does not change the result. It costs 0.25 ms for 5 sums over 1M cells on a GB10 (a fixed-order FP64 tree: 0.055 ms). The Euler physics runs unsteady cases on several ranks and with periodic pairs; its steady block Gauss-Seidel is coloured in one mesh's cell order, so steady cases run on one rank without pairs ([Registration](#registration)). Its generated face loops still sum each cell's faces in local face order, so a run repeats bit for bit at a fixed rank count, and across rank counts its norms and fields agree to round-off: within 256 ε of the precision, the largest difference relative to the field's largest magnitude (the largest speed for velocity components) and the norms' relative difference, measured at 7.5 ε on the norms and 11.3 ε on the fields after 12 steps on 4 ranks (`tests/physics/test_euler_run.cpp`). Bit for bit across rank counts awaits face loops that gather in ascending `face_global_id` (#199).

The ranks stop together after a signal reaches any of them, and report the least diverged cell of all. A physics failure on one rank records `E0704` with `data.rank` in `run.json`, then ends every rank with exit status 1.

| Member | Contract |
|---|---|
| `step(iteration)` | Advances one pseudo-time iteration (steady) or one time step (unsteady); returns a `StepReport`: one residual norm per equation of `residual_names(input)`, as results.md#history defines it; for unsteady runs the physical time advanced; and, if the state or a residual became non-finite or non-physical, the first offending cell. |
| `accumulate_average(weight)` | Adds the current state to the time average with that weight (the step's time step); called after each step past `average_from`. |
| `fields(mean)` | The cell fields of `field_names(input)`, in that order, current state or time average. |
| `residual_scales()` | A constant flux scale Φ_k per equation of `residual_names(input)`, finite and ≥ 0, or none (empty); called once after construction. In a steady `fp32+acc64` run, the runtime counts equation k converged once its residual is at most C · ε₃₂ · Φ_k (C = 0.5, ε₃₂ = 2⁻²³, [case-schema.md](case-schema.md#time)), if the `residual_orders` drop has not come first, and records these floors in run.json `convergence` ([case-schema.md](case-schema.md#time)). A wrong count or value is `E0704`. |
| `restart_fields()` | The cell-centred state beyond `fields(false)` that a `continue` needs to go on bit for bit (earlier time levels, averaging sums), written as `RestartState`; empty when there is none. |
| `wall_fields(faces)` | `Pressure`, `WallShearStressX`, `WallShearStressY`, `WallShearStressZ` on the given wall and slip faces. |
| `loads(zones, moment_center)` | Force and moment the fluid exerts on the boundary faces of the zones (results.md, forces monitor), in N and N·m; the runtime derives the coefficients. Called at each monitor iteration and once more on the final state of a converged, completed or stopped run, for run.json's `monitors`. A load or coefficient that is not finite fails the run with `E0704`: at a monitor iteration, the history stops at the line before. |

An exception from any member ends the run as `failed` with `E0704`. A report with a diverged cell or a non-finite residual ends it as `diverged` with `D0107`; the solution is then written only if every field is finite.

## Start

For an input with a `start` ([solver-input.md](solver-input.md)), the runtime checks the previous `solution.cgns` against `start.solution_sha256` (`E0709`), reads it (`E0707` if it cannot), and checks its mesh (`E0203`), precision and fields, and for `continue` its cell order (`E0708`). All of this happens before any directory exists. `PhysicsContext::start` then holds its `FlowSolution` and, for `continue`, its `FlowSolutionMean` and `RestartState`. The physics starts from those instead of `initial`. For `warm` it takes the fields only. A `continue` calls `step` from `start.iterations + 1`. The runtime carries on the physical time and the averaging interval, and measures steady convergence against `start.residual_reference`. A physics whose `restart_fields` round-trips its whole state makes the continued run reproduce the uninterrupted one: same history lines and same solution arrays.

## Registration

A build of `autan-run` lists its physics in a `PhysicsRegistry`: each entry matches `physics.kind`, `physics.turbulence.model`, `precision` and `devices.kind` (or `*`). An entry may also declare a scope, what it supports beyond its key (media, zones, conditions, the number of ranks the run spans, which it receives). The first match runs the case; no match, or a match whose scope refuses the input, is `E0706` before any directory exists, with `data.path` naming the offending key. The Euler physics refuses any cell zone that is not an ideal gas, cell zones of different gases (any property differs; `data.zone`, `data.medium`), boundary conditions other than slip, symmetry, farfield, inlet, outlet and manufactured (`data.zone`, `data.condition`), and a farfield point vortex in an unsteady case, with a nonzero sideslip or with a freestream at M ≥ 1 (`data.zone`). The input's `periodic` pairs must be the mesh's, and a periodic zone takes no condition (`E0705` otherwise). The Euler physics refuses steady cases with periodic pairs or on several ranks, and `oracle-state` conditions on several ranks ([Ranks](#ranks)). On a CUDA device it runs on one rank (`devices.kind`) and refuses a farfield point vortex (`data.zone`). Implementations templated on precision register one entry per precision they instantiate.
